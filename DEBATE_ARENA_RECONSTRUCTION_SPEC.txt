1.  What the Debate Arena Is
The Debate Arena is SARGE's multi-agent AI orchestration system. It is NOT a simple chatbot comparison. It is a structured adversarial debate engine where 2 - 3 AI agents argue a topic for N rounds, and a separate Judge agent produces a structured verdict.

This is one of the core patented features of SARGE. The specific combination of:
 User-controlled poison pill injection for testing
 Dispute isolation + auto-escalation to Round 2
 Full JSON artifact logging with detection metrics (echo kill rate, detection recall)
 Local-only execution with forensic audit trail
 Blind pass mode (agents cannot see who said what in previous rounds)

...is what distinguishes SARGE from existing multi-agent debate tools. File date: ~January 15 - 17, 2026.

2.2  Debate Execution Logic (Pseudocode)
   activeAgents = agents.filter(a => a.provider !== 'No LLM')

   for round in 1 to totalRounds:
     for agent in activeAgents:
       context = buildContext(previousRounds, passMode)
       // Blind mode: 'Participant N said:'  --  no role names
       // Sequential mode: full role + content visible
       messages = [system: agent.role, user: topic + context]
       response = await streamFromProvider(agent)
       roundResponses.push({ agent, response })

   // Judge runs AFTER all rounds complete
   judgePrompt = buildJudgePrompt(allRounds, topic)
   summary = await streamFromProvider(judge)

2.3  Pass Modes
Feature / ControlSpecification / BehaviorBlind PassEach agent sees previous round CONTENT but NOT role names or agent identity. Context shows 'Participant 1 said:'  --  prevents agents copying each other's framing. This is the key anti-echo-chamber mechanism.Sequential / Open PassEach agent sees full round history including role names and which model said what. Agents can reference each other directly.DefaultBlind Pass  --  always default to blind to prevent sycophancy cascade.
2.4  The 'No LLM' Option
If the user wants only 2 agents, they set Agent 3 to 'No LLM'. That slot is skipped entirely  --  no API call, no empty panel, no placeholder. The UI collapses or grays out that slot cleanly. The Judge always runs regardless.

5.  Judge Prompt Template
This is the exact structured prompt sent to the Judge after all agent rounds complete:

--------------------------------------------------------------------------------
  You are the judge in a multi-perspective debate.
   
  TOPIC: {topic}
   
  PARTICIPANTS AND THEIR ARGUMENTS:
   
  {for each round}
  --- Round {N} ---
  {for each agent}
  [{ROLE}]: {content}
  {/for}
  {/for}
   
  Provide a structured summary:
  1. CONSENSUS: Points all participants agreed on
  2. DISAGREEMENTS: Points of contention with different perspectives
  3. KEY INSIGHTS: Most valuable contribution from each role
  4. RECOMMENDATION: Your synthesis and recommendation
  5. CONFIDENCE: Rate reliability (Low/Medium/High) with reasoning

In Blind Pass mode, agents are anonymized in the judge prompt: '[Participant 1]:', '[Participant 2]:' instead of role names.

6.  Debate Engine  --  lib/debate/engine.ts
6.1  Type Definitions
   interface DebateAgent {
     id: string
     provider: string          // 'anthropic' | 'openai' | 'google' | 'xai' | 'ollama' | 'No LLM'
     model: string
     role: string              // '' | 'researcher' | 'engineer' | 'analyst' | 'critic' | 'custom'
     customPrompt?: string     // used when role === 'custom'
     color: string             // hex color for UI border
   }

   interface DebateRound {
     roundNumber: number
     responses: { agentId: string; content: string; model: string }[]
   }

   interface DebateConfig {
     topic: string
     agents: DebateAgent[]     // filter out 'No LLM' before use
     judge: DebateAgent
     totalRounds: number       // 1 - 5
     passMode: 'blind' | 'sequential'
   }

   interface DebateEvent {
     type: 'round_start' | 'chunk' | 'round_complete' | 'judge_start' | 'judge_chunk' | 'complete'
     agentId?: string
     roundNumber?: number
     chunk?: string
     debate?: Debate           // only on 'complete'
   }

   export async function* runDebate(

   ): AsyncGenerator<DebateEvent>

The engine yields events as the debate progresses. The UI subscribes and updates in real-time.

     setRounds: (n: number) => void

Store uses Zustand with persist middleware. Debate history is persisted to localStorage. Config (agents, topic, rounds) also persists so user doesn't have to reconfigure on each visit.

9.  Control Buttons  --  Exact Behavior
Feature / ControlSpecification / Behavior[Start]Validates config (topic not empty, at least 1 active agent). Calls startDebate(). Disables itself while running.[Pause]Sets isPaused = true. Current agent completes its response, then debate pauses before next agent/round starts. Does NOT cut off mid-stream.[Resume]Sets isPaused = false. Continues from where paused. Only visible when isPaused = true.[Redirect]Opens a small input modal mid-debate. User enters new prompt/direction. This is injected as additional context for the NEXT round. Agents receive: 'New direction from user: [redirect prompt]. Adjust your responses accordingly.'[Swap Judge]Opens a quick model-picker modal. User selects new judge provider + model. Takes effect for the judge summary step (not retroactively for rounds already done).[Stop]Immediately aborts via AbortController. All streaming halts. Debate marked as incomplete.[Export]Opens export options: PDF (full transcript + summary), JSON (raw data for forensics), Markdown (readable format). Saves to file.[Another Round]Appears in JudgeSummary after judge completes. Adds one more round with the same agents, then re-runs the judge.
